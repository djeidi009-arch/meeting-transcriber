# 0001. Оболочка на AppKit, содержимое окна на SwiftUI

## Контекст

Программа уже живёт на ручном запуске: `NSApplication`, делегат `StatusMenu`, значок в строке меню, запись, режим `--probe`. Окну нужен SwiftUI, при этом запись и меню должны остаться как есть.

## Решение

Запуск остаётся на AppKit: `main.swift`, `NSApplication` и делегат `StatusMenu`. Окно — обычный `NSWindow` с SwiftUI-содержимым внутри. Политика активации всегда `.regular`. Закрытие окна программу не завершает, а клик по значку в Dock открывает окно снова.

## Почему

- Переход на `@main App` с адаптером делегата отвергнут. Для него пришлось бы заменить `main.swift` (`@main` и `main.swift` в одном таргете не уживаются) и заново обеспечить `--probe` до старта App. Это риск для записи и разрешений без выигрыша для пользователя.
- Переключение политики `.accessory` ↔ `.regular` по открытию и закрытию окна отвергнуто. Значок в Dock мигал бы, а окно при `.accessory` может уходить за другие приложения.
- Оставить только строку меню и не делать окно нельзя: задача как раз в окне.

## Последствия

- Часть возможностей SwiftUI-приложений (сцены, `openWindow`, автоматическое восстановление окон) недоступна, окном и его положением занимаемся сами.
- Общее состояние пришлось вынести из `StatusMenu` в отдельный наблюдаемый слой `AppModel`; меню и окно обязаны ходить через него.
- Для открытия окна по клику в Dock нужен `applicationShouldHandleReopen`. Забудешь — программа, запущенная из LaunchAgent, на клик не ответит.
- Окно не должно открываться при входе в систему: нужен аргумент `--background`, который ставит LaunchAgent.
