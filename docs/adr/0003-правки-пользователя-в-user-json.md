# 0003. Названия и имена спикеров лежат в отдельном `user.json`

## Контекст

Название встречи — это `meta.app`, спикеры — только метки в `transcript.json`. Повторная обработка и повтор summary пересобирают `meeting.md` из этих файлов, поэтому любая правка внутри них была бы затёрта.

## Решение

Правки пользователя (название встречи и имена спикеров по меткам) хранятся в отдельном `user.json` в папке встречи. Пишет его только Swift, Python только читает. Метки в `transcript.json` и `meta.app` не меняются, имя накладывается при показе, экспорте и сборке `meeting.md`. Папка при переименовании не переименовывается.

## Почему

- Правка `transcript.json` (подмена меток) отвергнута: повторная обработка перезапишет файл, а исходную метку нельзя будет вернуть.
- Поле `speakerNames` в `meta.json` отвергнуто: `meta.json` пишет `MeetingStore`, а Python при этом пришлось бы всё равно учить читать новые поля. Два писателя в одном файле — путь к гонкам.
- Переименование папки отвергнуто: с именем папки связаны логи, ссылки из уведомлений и `recoverPending`.

## Последствия

- Имена живут вне `transcript.json`: кто его копирует отдельно, имён не увидит.
- Любой новый вывод (экспорт, summary, поиск) обязан накладывать `user.json` сам. Забыли — пользователь увидит «Спикер 1» там, где уже вводил имя.
- Summary, уже написанный Claude по меткам, имён не содержит, пока его не пересоздали повтором.
- Обе реализации (Python и Swift) читают один файл, формат нужно держать в согласии вручную.
