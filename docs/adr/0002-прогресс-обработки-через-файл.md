# 0002. Этап обработки передаётся файлом `progress.json`

## Контекст

Python не сообщает прогресс: stdout очередь отбрасывает, stderr читает целиком после завершения. Окну нужен текущий этап обработки, а тестовые фейки пайплайна имеют фиксированные сигнатуры.

## Решение

Python пишет в папку встречи `progress.json` (этап и необязательную долю) на границах четырёх этапов и удаляет его в конце, и при успехе, и при ошибке. Swift только читает файл, и только у задания, которое сейчас идёт. Статус встречи при этом не хранится, а вычисляется по файлам папки и снимку очереди.

## Почему

- Построчный вывод этапов в stdout с чтением через `Pipe` отвергнут. Пришлось бы переделать запуск процесса в очереди (сейчас stdout уходит в `/dev/null`, stderr читается блокирующе), а прогресс не пережил бы перезапуск окна.
- Колбэк прогресса внутри `asr`/`diarize` отвергнут: он меняет сигнатуры, на которых стоят фейки в тестах.
- Поле `status` в `meta.json` отвергнуто. Формат папки не меняется, старые встречи должны открываться сами, а записанный статус разошёлся бы с реальностью после падения.

## Последствия

- Если Python убит сигналом, `progress.json` остаётся. Читать его у неидущего задания нельзя, иначе покажется этап из прошлого запуска. Очередь стирает старый файл перед стартом задания.
- Внутри этапа точной доли обычно нет: она есть только для распознавания, как номер дорожки, в остальных случаях `null`.
- Упавший шаг в файле не сохраняется. После перезапуска ошибка показывается без отметки, на каком этапе она случилась.
- Статус «в очереди» нигде не записан: после перезапуска встреча без `meeting.md` и с `error.txt` снова встаёт в очередь.
