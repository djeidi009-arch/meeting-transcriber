## 3. Точные API DetectorCore и контракт с Python

`MeetingStore` (`public final class`, `init(outputDir: URL)`, `public let outputDir`):
- `static let recordingMarker = ".recording"`, `metaFile = "meta.json"`, `audioFiles = ["mic.caf","system.caf","mic.m4a","system.m4a"]`.
- `static func folderName(startedAt: Date, app: String) -> String` — `yyyy-MM-dd HH-mm <app>` (в app `/` и `:` → `-`; локаль en_US_POSIX, местное время).
- `func createMeeting(app: String, bundleID: String, manual: Bool, startedAt: Date = Date()) throws -> URL` — создаёт `outputDir` (если нет), папку `<folderName>` (коллизия → суффикс ` (2)`, ` (3)`…), `meta.json`, пустой маркер `.recording`.
- `func createImport(file: URL, at date: Date = Date()) throws -> URL` (новое) — `app` = имя файла без расширения, первые 60 символов; `bundleID: ""`, `manual: true`; в meta добавляет `sourceFile` = `file.standardizedFileURL.path`; удаляет `.recording`. Папка создаётся БЕЗ копирования исходника и без аудио.
- `@discardableResult func finishMeeting(_ dir: URL, endedAt: Date = Date(), minDuration: TimeInterval = 15) -> Bool` — пишет `endedAt`, снимает маркер; запись короче 15 с удаляется целиком (false).
- `func recoverPending(minDuration: TimeInterval = 15) -> [URL]` — вызывается один раз при запуске: доводит «осиротевшие» `.recording`, возвращает папки, где есть аудио (`audioFiles`) ИЛИ `meta.sourceFile`, но нет `meeting.md`. То есть папки с `error.txt` без `meeting.md` повторно ставятся в очередь при каждом запуске.
- `func recentMeetings(limit: Int = 5) -> [URL]` — только с `meeting.md`, новые первыми.
- `func lastMeetingWithTranscript() -> URL?` — первая с `transcript.json`.
- Внутри `private`: `meetingDirs()` (папки с `meta.json`, сортировка по `startedAt` убыв., затем по имени), `lastAudioWrite`, `writeMeta` (JSONSerialization `.prettyPrinted,.sortedKeys,.withoutEscapingSlashes`, atomic). `func readMeta(_:) -> [String: Any]?` — internal (не public) и `static func iso/parseISO` — internal: из таргета `MeetingTranscriber` недоступны; для окна понадобится public-слой чтения (список встреч, `Codable`-модель). Нет API: список всех встреч, переименование, удаление, запись meta, чтение transcript.json.

`ProcessingQueue` (`public final class`):
- `enum Kind: String { case process, resummarize }`, `struct Job: Equatable { dir: URL; kind: Kind }`, `static let exitSummaryFailed: Int32 = 2`, `enum Outcome { success; summaryFailed(String); failure(String) }`.
- `init(pythonPath: String, projectDir: URL, extraPath: [String] = [], logURL: URL? = nil, onBusyChange: @escaping (Bool) -> Void = { _ in }, onFinish: @escaping (Job, Outcome) -> Void)`.
- `var isBusy: Bool`, `func enqueue(_ dir: URL, kind: Kind = .process)` (дубликат Job, пока в очереди или идёт, молча игнорируется), `func waitUntilIdle(timeout:) -> Bool`, `func cancelAll()`.
- `pending` и `running` — private: снаружи нельзя узнать, «в очереди» или «идёт» конкретная папка, и нет колбэка «задание началось». Для статусов «в очереди/расшифровывается» нужно добавить публичное состояние (например `onStart`, `snapshot()` → `(running: Job?, pending: [Job])`) — это правка DetectorCore + selftest.
- Запуск Python (`execute`): `Process`, `executableURL = pythonPath`, `arguments = ["-m","transcriber","process"|"resummarize", dir.path]`, `currentDirectoryURL = projectDir`, окружение = окружение процесса + `PATH = extraPath + [старый PATH]` (старый по умолчанию `/usr/bin:/bin:/usr/sbin:/sbin`) + `PYTHONUNBUFFERED=1`; stdin и stdout → `/dev/null` (stdout сейчас выбрасывается!); stderr → `Pipe`, читается `readDataToEndOfFile()` ПОСЛЕ завершения (то есть живого стрима stderr нет). Лог: дописывает в `processing.log` заголовок `=== <Date> <kind> <путь> → код N` + весь stderr.
- Коды выхода: 0 и `.exit` → `.success`; 2 → `.summaryFailed(последняя строка stderr)`; иначе `.failure(...)`: приоритет — первая непустая строка свежего `error.txt` (изменён после старта задания), затем последняя строка stderr, затем «Обработка прервана (сигнал N)», затем «Обработка завершилась с кодом N». Не удалось запустить → `.failure("Не удалось запустить обработку (<pythonPath>): ...")`.
- Как определяется состояние сейчас (только по факту файлов и очереди): «идёт запись» — есть `.recording`; «готово» — есть `meeting.md`; «ошибка» — `error.txt` (пишет Python при исключении, удаляется при успешном `process`); «в очереди/идёт» — нигде не хранится, только `ProcessingQueue.pending/running` в памяти (и `processing: Bool` в StatusMenu). Нюанс: при `resummarize` с неудачным summary `meeting.md` перезаписывается текстом «Summary не удалось сделать: …», а код выхода — 1 (ProcessingError), не 2; при `process` с падением summary — код 2 и `meeting.md` с тем же текстом. Статус «готово без summary» различим только по тексту в `meeting.md`.

`AppConfig` (`public struct`): поля `outputDir: URL`, `language: String`, `claudePath: String`, `pythonPath: String`, `summaryTimeoutSec: Int`, `extraBundleIDs: [String]`, `extraTitlePatterns: [String]`; `static var defaultURL` = `~/.config/meeting-transcriber/config.json`; `static func defaults(projectDir: URL) -> AppConfig`; `static func load(from: URL = defaultURL, projectDir: URL) -> AppConfig` (нет файла/ключа → default; `~` раскрывается). Реального config.json на машине: outputDir `~/transcripts`, claudePath из nvm, pythonPath = `<проект>/.venv/bin/python`. Python-копия — `transcriber/config.py` (`Config`, `load()`; ключ меняешь — правь обе).

Модель `meta.json` (пишет Swift `MeetingStore`, читает `pipeline._read_meta` и `render`; ключи `JSONSerialization`, отсортированы):
- `app: String` — имя приложения ИЛИ имя файла (для импорта). Это единственный «заголовок» встречи: идёт в `# <app> — ДД.ММ.ГГГГ ЧЧ:ММ` в meeting.md. Папка при смене `app` не переименовывается.
- `bundleId: String` (`""` для ручной встречи без известного приложения и для импорта), `startedAt: String` ISO8601 с локальным смещением (`2026-11-10T18:56:22+07:00`), `endedAt: String | null` (null во время записи и у импорта навсегда), `manual: Bool` (true для ручного старта и для импорта), `sourceFile: String?` (только импорт, абсолютный путь исходника).
- Поля `status`/`title`/`speakers`/`progress` в meta НЕТ. Если Python не находит meta.json — `app` берёт из имени папки регэкспом, `startedAt/endedAt = None`.
- `meta.json` пишут только Swift (`createMeeting`, `createImport`, `finishMeeting`); Python его не меняет.

## 4. Формат файлов встречи по факту (`~/transcripts`, 15 папок)

- Имя папки `ГГГГ-ММ-ДД ЧЧ-ММ <app>[ (N)]`, например `2026-11-03 14-40 Zoom`, `2026-11-06 19-02 Встреча`, `2026-11-05 16-43 Телемост`, импорт — `2026-11-10 18-56 20261110-1120-49.1942910` (имя исходного файла). Время в имени — местное (+07:00).
- Состав обработанной папки: `meeting.md`, `meta.json`, `transcript.json`, `system.m4a`, `mic.m4a` (14 из 15; у импорта `mic.m4a` нет). `.caf` не осталось ни одного: после успеха Python сжимает `.caf` → `.m4a` (AAC 64 кбит/с, моно/как есть, `-vn`) и удаляет `.caf`. Записываются `.caf` (Recorder), читать надо `.m4a`; при необработанной/упавшей встрече остаются `.caf`. Размеры: ~6–7 МБ на 15 мин на дорожку; импорт 2 мин → 1 МБ. `error.txt` в живых папках нет. `.recording` нет.
- Новейшая (импорт из mp4 на Рабочем столе): meta содержит `sourceFile` (путь `.mp4`), `endedAt: null`, `manual: true`, `bundleId: ""`, `app` = имя файла. Единственная папка с `sourceFile`. Исходное видео остаётся ТОЛЬКО по пути `sourceFile` (не копируется): для плеера видео брать `sourceFile`, если файл существует; у `system.m4a` видеоряда нет (`-vn`). Если пользователь удалил/переместил исходник — остаётся только `system.m4a`.
- `transcript.json`: `{"utterances": [ {start: float, end: float, speaker: String, text: String}, ... ], "duration": float}`, indent=1, ensure_ascii=False. `duration` — длина самой длинной дорожки в секундах (у встречи ~892.25). Слов (word timestamps) НЕТ — только реплики; сегменты ≤ ~28 с нарезаны VAD, подряд идущие реплики одного спикера склеены, если пауза ≤ 30 с (`merge.combine`), то есть реплика может быть длинной. Спикеры: `"Я"` (дорожка микрофона, константа `merge.ME`) и `"Спикер 1"`, `"Спикер 2"`… (диаризация system-дорожки, нумерация по порядку первого появления). У импорта один «Спикер 1» на 124 с — одна реплика на весь файл (диаризация не разделила). Один и тот же «Спикер N» не связан между встречами.
- `meeting.md`: строка 1 `# <app> — ДД.ММ.ГГГГ ЧЧ:ММ` (без даты, если нет startedAt), пустая, `Длительность: <N ч M мин | M мин | N с>`, пустая, `## Summary`, затем Markdown от Claude с четырьмя блоками `### Кратко`, `### Решения`, `### Задачи`, `### Открытые вопросы` (при сбое: строка «Summary не удалось сделать: <причина>. Меню → Повторить summary»; при пустой речи: «Summary нет: в записи нечего обобщать.»), затем `## Транскрипт`, и реплики по абзацу: `**[чч:мм:сс] Спикер N:** текст`, между ними пустая строка. Таймкоды целые секунды (`int`), из meta/transcript в meeting.md точной длительности нет.
- Где имена спикеров: ТОЛЬКО как метки в `transcript.json` (`speaker`) и в `meeting.md` (в тексте реплик и, возможно, в summary, который Claude пишет по меткам «Я»/«Спикер N»). Отдельного хранилища имён нет. Название встречи — `meta.app` (отдельно от имени папки; папка остаётся прежней). Переименование спикеров/встречи = править `meta.json`/`transcript.json` (и пересобрать `meeting.md` или читать из `transcript.json`); учти, что `resummarize` и `process` не знают про кастомные имена и перезапишут `meeting.md` метками из `transcript.json`/`meta.app` (`resummarize` читает speaker из transcript.json, `app` из meta — если переименовывать там, переживёт). Если решишь добавить `speakerNames` в meta — Python (`render`) надо учить.
- Для поиска по тексту удобнее `transcript.json`, а не `meeting.md`.

## 5. Python-пайплайн

- Вход `transcriber/__main__.py`: `python -m transcriber {process|resummarize} <папка>`; `config.load()`; `process` → код 2 при `summary_error` (сообщение в stderr), любое исключение → одна строка по-русски в stderr и код 1; `KeyboardInterrupt` → «Обработка прервана», код 1. Константа `EXIT_SUMMARY_FAILED = 2` (дублируется в Swift).
- `pipeline.process(meeting_dir, cfg, asr=None, diarize=None, summarize=None) -> str | None` (зависимости подставляются параметрами — так работают тесты); если есть `meeting.md` — сразу выход (на готовой папке ничего не делает). Исключения: `_record_error` пишет `error.txt` (одна строка) и пробрасывает дальше.
- `_process` по порядку:
  1. Проверка маркера `.recording` → `ProcessingError("Запись ещё идёт ...")`.
  2. `_read_meta(meeting_dir)`.
  3. `_import_source(meeting_dir, meta)` — этап «извлечение звука» для импорта: если есть `meta.sourceFile` и нет ни `mic.*`, ни `system.*` → файл должен существовать (`ProcessingError("Файл не найден: ...")`), затем `audio.to_m4a(src, meeting_dir/"system.m4a")` (ffmpeg `-vn -c:a aac -b:a 64k`, через временный `.part.m4a`). Если `system.m4a` уже есть (повторная попытка) — шаг пропускается.
  4. Для `track in ("mic","system")`: `_track_source` (`.caf` приоритетнее `.m4a`) → `audio.to_wav16k(src, tmp/<track>.wav)` (ffmpeg → моно 16 кГц; False — немая/пустая дорожка), `audio.wav_duration`, для `.caf` больше 4096 Б → `audio.to_m4a(caf, <track>.m4a)`; затем `asr(wav, cfg.language)` (`asr.transcribe`: VAD-нарезка `vad.speech_regions` ≤ 28 с → mlx_whisper large-v3-turbo, фильтр галлюцинаций); только для `system` и только если есть сегменты — `diarize(wav)` (pyannote community-1, MPS).
  5. `merge.assign_speakers` → `merge.mic_utterances` → `merge.drop_echo` → `merge.combine`.
  6. Запись `transcript.json` (атомарно, `_write_atomic`).
  7. `_summarize` → `summary.summarize(transcript_text, claude_path, timeout)` (`claude -p --output-format text --tools "" --strict-mcp-config --no-session-persistence`, текст в stdin, `SummaryError(reason)`); пусто → summary None без ошибки.
  8. `render.render_markdown(...)` → `meeting.md` (атомарно).
  9. Очистка: `error.txt` удаляется, `.caf` удаляются, если есть `.m4a` или файл пустой.
- `resummarize`: читает `transcript.json` (иначе `ProcessingError("Нет транскрипта ...")`), `_summarize`, переписывает `meeting.md`; при `summary_error` ещё и бросает `ProcessingError` (поэтому код 1, не 2).
- ПРОГРЕССА СЕЙЧАС НЕТ: Python ничего не печатает в stdout, в stderr — только ошибки и предупреждения библиотек; Swift stdout отбрасывает, stderr читает целиком после выхода. Нет файла прогресса. Логирования (`logging`) тоже нет.
- Где сообщать этап: границы этапов в `_process` — после `_import_source` (звук извлечён), внутри цикла по трекам перед `asr(...)` (распознавание) и перед `diarize(...)` (спикеры), перед `_summarize(...)` (summary), после записи `meeting.md` (готово). Самый простой контракт без переделки очереди: Python пишет атомарно `progress.json` в папку встречи (`{"stage": "extract|asr|diarize|summary", "track": ..., "updatedAt": ...}`) и удаляет в конце/при ошибке, а Swift опрашивает файл (или `DispatchSource` на папку); альтернатива — печатать строки в stdout и читать `Pipe` построчно в `ProcessingQueue.execute` (сейчас stdout=`nullDevice`; stderr читается блокирующе до EOF — для живого чтения заменить на `readabilityHandler`). Колбэк внутри asr/diarize (процент) сейчас не предусмотрен: `asr.transcribe` обрабатывает участки циклом (можно считать долю по участкам VAD), `diarize` — один вызов pipeline без прогресса. Тестовые фейки `AsrFn/DiarizeFn/SummarizeFn` имеют фиксированные сигнатуры (`Callable[[Path,str], list[Segment]]` и т.д.): прогресс лучше слать из `_process`, а не менять сигнатуры.
- Длительность: этап asr на модели large-v3-turbo идёт минуты (первый запуск ещё качает модели ~1.6 ГБ); processing.log показывает код выхода и stderr, время в UTC.

## 6. Проверки и стиль

- `make check` = `uv run pytest` (testpaths `tests/`, файлы `test_asr|config|merge|pipeline|render|summary|vad.py`; в рабочем дереве +2 теста импорта в `test_pipeline.py`: `test_process_imported_video_extracts_audio_as_system_track` (нужен ffmpeg, libx264, генерирует mp4) и `test_process_imported_missing_file_fails_in_russian`) + `cd app && swift run selftest`. По AGENTS.md pytest 48 / selftest 86 проверок (в рабочем дереве после правок цифры могут быть другими: `grep -c "test("` по `app/Sources/selftest/` даёт 2+3+17+3+5 тестов в 5 наборах; число `check(...)` не пересчитывал). Тяжёлые модели в тестах не грузить, `claude` не вызывать.
- `selftest`: без XCTest (его нет на Command Line Tools). `app/Sources/selftest/main.swift` содержит свои `check(_ condition: @autoclosure () -> Bool, _ message:)` и `test(_ name:, _ body: () throws -> Void)` (счётчики `passed`/`failures`, печать `ok`/`FAIL`), общий хелпер `run(detector:...)`; в конце вызовы `DetectorTests.all()`, `StoreTests.all()`, `ConfigTests.all()`, `QueueTests.all()`, `AlignerTests.all()`, потом `print("\(passed) checks passed, \(failures) failed")`, `exit(0|1)`. Новый набор: файл `XxxTests.swift` в `app/Sources/selftest/` с `enum XxxTests { static func all() { test("...") { ... } } }` + строка `XxxTests.all()` в `main.swift`. Хелперы в `StoreTests.swift` (доступны во всём таргете): `tempDir(_:)`, `readJSON(_:)`, `exists(_:)`, `touch(_:_:modified:)`, `localDate(y,mo,d,h,mi,s)`; в `QueueTests.swift` — `makeFakePython(in:log:)` (sh-скрипт, падает на путях со словами `bad`/`bad2`/`sumfail`). Тестировать можно только то, что в DetectorCore (selftest зависит только от него); код `MeetingTranscriber` (AppKit/SwiftUI) selftest не видит — логику окна (модели списка, группировка по дням, поиск, статусы, парсинг transcript) выноси в DetectorCore.
- Стиль Swift: комментарии `///` и `//` — по-русски, коротко, про «почему»; тексты интерфейса и ошибок — по-русски; имена типов/функций — английские; `// MARK: - название` на русском («запуск», «запись», «меню»); `@objc private func xxxClicked()` для действий меню; без внешних зависимостей; Foundation-only в DetectorCore; `Task { @MainActor in ... }` для перехода на main. Python: докстринги по-русски, `from __future__ import annotations`, dataclass `frozen=True`, сообщения об ошибках по-русски одной строкой, тесты pytest с фейками (`Fakes`) без тяжёлых моделей.
- Лишнее: Python-тесты зависят от `ffmpeg` в PATH/Homebrew.

## 7. Подводные камни для нового окна

- `LSUIElement=true` и `setActivationPolicy(.accessory)` (в `main.swift`): окно без Dock-значка, при `.accessory` окно может уйти за другие приложения; сейчас для NSOpenPanel вызывается `NSApp.activate(ignoringOtherApps: true)`. Нужна смена policy на `.regular` (при открытии окна и закрытии — вернуть `.accessory`, либо всегда `.regular` и убрать `LSUIElement`; тогда значок в Dock появляется, а «Выход» из статус-меню остаётся). После `setActivationPolicy(.regular)` выставить `NSApp.activate`.
- Цикл запуска ручной (`NSApplication.shared` + делегат + `app.run()`): SwiftUI `@main App` рядом использовать нельзя без переделки `main.swift`; проще оставить AppKit-запуск и поднять SwiftUI-окно через `NSHostingController`/`NSWindow` (или `NSHostingView`), либо перейти на `@main struct App` с `@NSApplicationDelegateAdaptor` — тогда `main.swift` заменяется (в executableTarget `@main` и `main.swift` одновременно нельзя) и `--probe` нужно сохранить (проверка аргументов до запуска App).
- `StatusMenu` — «бог-объект», всё `private`. Статусы живут в памяти и в таймерах; общий наблюдаемый слой (store + queue + запись) отсутствует — нужно создать. `Timer` 1 с и `menuNeedsUpdate` — единственные «подписки».
- `ProcessingQueue` не отдаёт состояние заданий и не стримит вывод; колбэки приходят с фоновой очереди. `enqueue` молча игнорирует дубликат. `cancelAll()` вызывается только при выходе. Нет «отмены одного задания» и «повторить после ошибки» (после ошибки встреча повторно ставится в очередь только при следующем запуске через `recoverPending`).
- Имя бандла и процесса `MeetingTranscriber` зашито: `pkill -x MeetingTranscriber` в `install.sh`/`uninstall.sh`; `CFBundleExecutable`, путь `build/MeetingTranscriber.app`, `~/Applications/MeetingTranscriber.app`, `codesign --identifier ru.local.meeting-transcriber` и designated requirement по этому идентификатору (чтобы TCC помнил разрешения; смена bundle id = новые запросы микрофона/записи экрана), Label LaunchAgent, README и AGENTS.md. Менять название на «Транскрибатор» — только `CFBundleDisplayName`/`CFBundleName`, не идентификатор и не исполняемый файл.
- LaunchAgent запускает `.../Contents/MacOS/MeetingTranscriber` при входе; `ProcessType: Interactive`. При клике по Dock/Spotlight, если приложение уже запущено из LaunchAgent, срабатывает reopen — нужен `applicationShouldHandleReopen`, иначе окно не откроется. Окно при автозапуске при входе открываться не должно (или по настройке).
- Пути логов: `~/Library/Logs/MeetingTranscriber/processing.log` (Swift очередь, заголовок + stderr), `app.log` (stderr из LaunchAgent, пишется только при запуске через launchd).
- Ключи: `UserDefaults.standard` — `autoRecord` (Bool, default false, `StatusMenu.autoRecordKey`; домен = bundle id `ru.local.meeting-transcriber`, при `swift run` — другой домен); ничего больше приложение само не хранит (в defaults сейчас лишь `NSNavPanel*` от NSOpenPanel). Если окно хранит состояние (выбранная встреча, сортировка), заведи новые ключи с префиксом. Конфиг — `~/.config/meeting-transcriber/config.json` (читается ОДИН раз при запуске; изменение требует перезапуска).
- `MTProjectDir` в Info.plist: путь проекта нужен для cwd Python; приложение не работает без проекта на диске (`.venv`, `transcriber/`). Бандл не самодостаточен.
- Уведомления: `Notifier` — отдельный класс, клик открывает `meeting.md` во внешней программе; настроен единственный делегат `UNUserNotificationCenter`.
- Разрешения (TCC): микрофон и запись экрана ad-hoc подписанному приложению; после пересборки могут слететь. Новые разрешения (календарь — «задел») понадобятся ключи вроде `NSCalendarsFullAccessUsageDescription` в Info.plist.
- Воспроизведение: исходное видео нужно открывать по `meta.sourceFile` (путь вне `~/transcripts`; песочницы нет, TCC на Рабочий стол/Документы может потребовать разрешения папок); для импорта аудио — `system.m4a`; для обычной встречи — две дорожки `mic.m4a` и `system.m4a` (общего микса нет — для одного плеера либо микшировать в `AVMutableComposition`, либо играть `system.m4a`; на импорте `mic.m4a` отсутствует).
- Таймкоды реплик — относительно начала дорожек (0 = старт записи, выравнивается `TrackAligner`), совпадают с позицией в `system.m4a`/`mic.m4a`; у импорта — с позицией в исходном файле (для видео в плеере те же секунды, если у видео нет смещения старта аудио).
- `meetingDirs()` считает встречей любую папку с `meta.json` в `outputDir`; файлы `.DS_Store` в `~/transcripts` игнорируются (скрытые пропускаются). Список встреч в окне нужен без чтения `transcript.json` целиком (на 15 мин ~31 КБ, терпимо), но `startedAt` и `app` брать из meta.
- Побочные тонкости: время в meeting.md и имени папки — местное (текущий часовой пояс), `processing.log` — по UTC; `startedAt` парсится `ISO8601DateFormatter` с `.withInternetDateTime` (смещение `+07:00` поддерживается).
- Стили/сборка: SwiftUI-код в `MeetingTranscriber` потребует `import SwiftUI` и, возможно, AVKit; `swiftLanguageModes: [.v5]` — не включит строгую проверку конкурентности, но `@MainActor`-изоляция в StatusMenu уже есть.
