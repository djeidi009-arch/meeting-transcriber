## Что должно заработать

Окна ещё нет, но всё, что оно будет показывать, уже можно получить и проверить. Обработка встречи сообщает, на каком она этапе (извлечение звука → распознавание речи → спикеры → summary), через файл `progress.json` в папке встречи. Название встречи и имена спикеров хранятся в `user.json`, не теряются при повторной обработке и попадают в `meeting.md`. В `DetectorCore` появляется библиотека встреч: список со статусами (идёт запись / в очереди / расшифровывается / готово / ошибка), группировка по дням, поиск по названию и тексту, документ встречи для показа и экспорта (Markdown и простой текст), набор выдуманных демо-встреч. Очередь обработки отдаёт, что идёт сейчас и что ждёт.

Интерфейса этот таск не делает и `app/Sources/MeetingTranscriber/` не трогает (кроме случая, когда без однострочной правки вызова не соберётся).

## Критерии приёмки

- [ ] `process` на папке встречи пишет `progress.json` с этапами строго по порядку `extract → asr → diarize → summary` и удаляет его в конце — и при успехе, и при ошибке (pytest с существующими фейками)
- [ ] `resummarize` пишет только этап `summary`; при сбое summary выходит с кодом 2, транскрипт цел
- [ ] `user.json` с названием и именами спикеров: `meeting.md` после `process` и `resummarize` содержит название и имена; `transcript.json` хранит исходные метки; без `user.json` и с битым `user.json` всё работает как раньше
- [ ] `ProcessingQueue.snapshot()` показывает идущее и ждущие задания, `onChange` срабатывает при постановке, старте и завершении (selftest с фейковым python)
- [ ] `MeetingLibrary.items` на временной папке даёт верный статус для каждого случая: `.recording`, в очереди, идёт (с этапом из `progress.json`), `meeting.md`, `error.txt`, summary не удалось (`summaryFailed`), старая папка без новых файлов
- [ ] `title` берётся из `user.json`, иначе из `meta.app`; `setTitle`/`setSpeakerName` пишут `user.json` атомарно, пустое значение возвращает исходное
- [ ] `sections` группирует по дням: «Сегодня», «Вчера», «5 ноября», прошлый год — с годом; новые сверху
- [ ] `search` находит по названию и по тексту реплик без учёта регистра и «ё/е», отдаёт до трёх фрагментов с таймкодом; пустой запрос — все встречи
- [ ] `MeetingDocument.markdown()` даёт формат `meeting.md` с подставленными именами; `plainText()` — summary и реплики без разметки; `speakerShares()` в сумме даёт 1
- [ ] `DemoLibrary.create` создаёт 6–8 выдуманных встреч в настоящем формате (разные дни, готовые, одна с ошибкой, одна без summary), и `MeetingLibrary` их читает
- [ ] `make check` проходит; новых проверок: Python ≥ 6, Swift ≥ 25
